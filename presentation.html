03 / 05
Resolving High Latency & Token Exhaustion in Concurrent RAG
🚨
Issue Detected
High API latency spikes and LLM token exhaustion during concurrent RAG inference under peak traffic load.
🔍
Root Cause
Overly large, poorly chunked text segments retrieved from the vector DB were flooding the LLM context window, causing context overflow and slow generation.
📊
Diagnosis
FastAPI endpoint profiling confirmed the bottleneck was in the vector retrieval payload size — not in the LLM generation step itself.
✅
Resolution
Implemented semantic chunking + a Cross-Encoder re-ranker — reduced retrieval payload from ~8,000 tokens (all chunks) down to a precise top-3 snippets (~600 tokens), a 93% token reduction.
Before vs After
❌ Before ~8,000 tokens → LLM ~2,400ms
✅ After ~600 tokens (top 3) 0.46ms
Fix
Semantic Chunking
Ranker
Cross-Encoder
💡 Key Learning
Context precision is far more critical than context quantity. Passing 3 highly-relevant snippets consistently outperforms passing 20 loosely-relevant ones.
